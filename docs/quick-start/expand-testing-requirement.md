# Expand Testing 练习需求文档

## 文档说明

本文档用于在 `WHartTest -> 需求管理` 中做首轮演示，目标不是描述真实业务，而是提供一份结构清晰、适合拆分模块和评审的练习需求。

- 推荐用途：需求上传、模块拆分、需求评审、生成测试用例
- 推荐文档类型：`Markdown`
- 推荐拆分方式：按标题层级拆分

## 1. 背景

测试团队需要基于公开练习站点 `Expand Testing Practice` 对平台原始能力进行验证，验证范围包括：

- 项目创建与项目隔离
- 需求文档上传与模块拆分
- 需求评审能力
- 用例生成能力
- UI 自动化执行能力

目标站点地址：

- `https://practice.expandtesting.com/`

## 2. 用户登录模块

### 2.1 登录入口

系统应提供登录页面，页面地址为：

- `/login`

登录页至少应包含：

- 用户名输入框
- 密码输入框
- 登录按钮

### 2.2 登录成功

当用户输入正确用户名和密码后，系统应：

- 跳转到安全区域页面
- 页面 URL 应包含 `/secure`
- 页面应显示登录成功提示
- 页面应提供退出登录入口

练习账号如下：

- 用户名：`practice`
- 密码：`SuperSecretPassword!`

### 2.3 用户名错误

当用户名错误但密码格式正确时，系统应：

- 保持在登录页
- 提示用户名错误
- 不应进入安全区域

### 2.4 密码错误

当用户名正确但密码错误时，系统应：

- 保持在登录页
- 提示密码错误
- 不应进入安全区域

## 3. 表单输入与基础交互模块

### 3.1 基础输入

系统应提供基础输入页，支持用户输入文本、数字或其他简单表单数据。

输入后应支持：

- 页面回显输入内容，或
- 能通过界面状态验证输入生效

### 3.2 表单校验

对于必填项或非法输入，系统应提供可识别的校验提示。

至少需要验证：

- 必填项为空
- 格式非法
- 正常输入提交成功

## 4. 动态加载模块

### 4.1 加载触发

系统应存在动态加载场景。用户触发某个动作后，页面经过一段加载时间再显示结果。

### 4.2 结果展示

加载完成后，页面应：

- 显示预期内容
- 或显示新的可交互区域

### 4.3 自动化要求

自动化执行时应支持：

- 显式等待
- 结果出现后的断言
- 避免用固定长时间睡眠代替状态判断

## 5. IFrame 模块

### 5.1 页面结构

系统应包含嵌入式 `IFrame` 页面，框架内部存在可编辑区域或可交互控件。

### 5.2 自动化要求

自动化执行时应支持：

- 切换到指定 IFrame
- 在 IFrame 内完成输入或断言
- 操作完成后回到主文档

## 6. Shadow DOM 模块

### 6.1 页面结构

系统应包含 `Shadow DOM` 场景，页面中的目标元素不是直接暴露在普通 DOM 结构中。

### 6.2 自动化要求

自动化执行时应支持：

- 正确定位 Shadow DOM 中的目标元素
- 获取元素状态或文本
- 对关键结果做断言

## 7. 多窗口模块

### 7.1 打开新窗口

系统应支持通过点击链接或按钮打开新窗口或新标签页。

### 7.2 自动化要求

自动化执行时应支持：

- 捕获新窗口
- 切换到新窗口
- 断言新窗口页面内容
- 必要时关闭新窗口并返回原窗口

## 8. 非功能要求

### 8.1 稳定性

自动化脚本不应依赖不稳定的动态 ID 作为唯一定位方式。

### 8.2 可观测性

执行过程应尽量保留以下信息：

- 执行日志
- 截图
- Trace

### 8.3 可维护性

建议优先使用清晰、稳定的定位方式，例如：

- 文本
- Label
- Role
- 明确的 CSS 选择器

## 9. 首轮验收标准

完成首轮平台联调时，至少应满足：

- 能从需求文档中拆分出多个模块
- 能完成至少一次需求评审
- 能从登录或基础交互模块生成测试用例
- 能把生成出的结果映射到 UI 自动化场景中
- 能最终执行并查看结果
